# Storage

Self-hosted Kagibi runs on a shared Docker Compose base (`docker-compose.yaml`: PostgreSQL, Redis, backend, frontend) plus a choice of **object storage backend**, toggled with an optional second Compose file:

| | Files to run | Storage | Where data lives |
|---|---|---|---|
| **Option A — External S3** | `docker-compose.yaml` alone | OVH Object Storage, AWS S3, Scaleway, Cloudflare R2, managed MinIO... | With the S3 provider |
| **Option B — Local (Garage)** | `docker-compose.yaml` + `docker-compose.garage.yml` | [Garage](https://garagehq.deuxfleurs.fr/), S3-compatible, self-hosted | On your own disk/NAS |

In both cases the Kagibi backend is unchanged — it always speaks the S3 protocol (`backend/pkg/s3storage/client.go`). Only the destination changes.

**Which to pick?** Option A suits you if you'd rather hand data durability to a provider (multi-AZ replication, SLA) without managing disks yourself. Option B suits you if you want the files — already end-to-end encrypted client-side — to never leave your own hardware, typically a NAS with RAID/ZFS for durability.

## Option A — External S3 storage (OVH Object Storage)

### 1. Create an S3 container (bucket) at OVH

In the OVH manager: **Public Cloud → Object Storage → Create a storage object**, type **Standard** (or High Performance as needed), pick a region (e.g. `gra` — Gravelines, `sbg` — Strasbourg, `de` — Frankfurt, `waw` — Warsaw). Note the region and container name.

### 2. Generate S3 credentials

Under **Object Storage → User management** ("S3 Users"), create a user with read/write rights on the container. OVH provides an **Access Key** and a **Secret Key** — the secret is shown in clear only once, copy it immediately.

### 3. Configure the bucket's CORS (required)

The browser uploads/downloads files **directly** to the S3 bucket via presigned URLs generated by the backend — without this step, those cross-origin requests fail silently (CORS errors only visible in the browser console).

```bash
cp scripts/s3-cors-config.example.json scripts/s3-cors-config.json
# Edit scripts/s3-cors-config.json: set AllowedOrigins to your domain(s)
#   e.g. ["https://your-domain.example"]

aws s3api put-bucket-cors \
  --endpoint-url https://s3.<region>.io.cloud.ovh.net \
  --bucket <container-name> \
  --cors-configuration file://scripts/s3-cors-config.json
```
(requires the AWS CLI, configured with the step-2 credentials — `aws configure` or `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` env vars for this one command).

### 4. Fill in `.env`

Reopen the `.env` file created during the common prerequisites (the one that already has `JWT_SECRET`, `DB_PASSWORD`, etc.) and fill in the 5 S3 variables left empty:

| Variable | OVH example |
|---|---|
| `S3_ENDPOINT` | `https://s3.gra.io.cloud.ovh.net` |
| `S3_BUCKET` | `<container-name>` |
| `S3_REGION` | `gra` |
| `S3_ACCESS_KEY` | `<step 2 Access Key>` |
| `S3_SECRET_KEY` | `<step 2 Secret Key>` |

### 5. Launch

```bash
docker compose up -d --build
```

### 6. Verify

```bash
curl http://localhost:8080/health          # {"status":"ok"}
docker compose logs -f backend             # no "S3 configuration is missing" error
```
Then, in the app: create an account, upload a file, download it — confirms the presigned path (backend → browser → S3 → browser) works end to end.

### Maintenance

- **Update**: `git pull && docker compose up -d --build`.
- **Backup**: file durability is delegated to the provider (multi-AZ replication at OVH). Only PostgreSQL (`db_data/`) holds metadata (tree structure, encrypted file keys, accounts) — back it up separately (regular `pg_dump` or volume snapshot).

### Troubleshooting

| Symptom | Likely cause |
|---|---|
| `S3 configuration is missing` in backend logs | One of the 5 `S3_*` variables is empty in `.env` |
| Upload stuck, CORS error in browser console | Step 3 not done, or CORS `AllowedOrigins` doesn't exactly match the served origin (scheme + domain + port) |
| `403 Forbidden` on S3 requests | Invalid Access/Secret Key, or the S3 user lacks write access to the container |

## Option B — Fully local storage (Garage)

### 0. Decide the browser-reachable address

Unlike the backend (which can talk to Garage over Docker's internal network), presigned URLs handed to the **browser** must point to an address it can actually resolve: your machine/NAS's LAN IP (`http://192.168.1.50:3900`) or a domain behind a TLS reverse proxy (`https://s3.your-domain.example`). Decide this now — it's used in step 3.

### 1. Configure Garage

```bash
cp garage/garage.toml.example garage/garage.toml
```
Edit `garage/garage.toml` and replace the two placeholders with generated secrets:
```bash
openssl rand -hex 32   # → rpc_secret
openssl rand -hex 32   # → admin_token
```
`garage.toml` is git-ignored (`.gitignore`) — never commit it with real secrets.

### 2. Create the credentials placeholder file

```bash
mkdir -p garage/credentials && touch garage/credentials/s3.env
```
Required even empty: Docker Compose validates that every referenced `env_file:` exists before starting anything — without this file, `docker compose up` refuses to start. It gets filled automatically on first launch by `garage-init`.

### 3. Fill in `.env`

Reopen the same `.env` file created during the common prerequisites (the one that already has `JWT_SECRET`, `DB_PASSWORD`, etc.) and add:

```bash
# Required — see step 0
GARAGE_PUBLIC_ENDPOINT=http://192.168.1.50:3900

# Optional — defaults already consistent across garage.toml, bootstrap.sh and the backend
# GARAGE_S3_PORT=3900
# GARAGE_S3_REGION=garage
# GARAGE_BUCKET=kagibi
# GARAGE_KEY_NAME=kagibi-key
# GARAGE_CAPACITY=10G
```
The 5 `S3_*` variables from the previous section don't need to be filled in here, even if they're still empty in `.env`: `docker-compose.garage.yml` automatically overrides them for the `backend` service — no need to touch them for this option.

### 4. Launch

```bash
docker compose -f docker-compose.yaml -f docker-compose.garage.yml up -d --build
```
On first launch, `garage-init` waits for the Garage node to respond, assigns the layout (required even for a single node), creates the bucket and an S3 key, then writes `garage/credentials/s3.env` — the backend only starts once this step has completed successfully (`depends_on: condition: service_completed_successfully`).

### 5. Verify the bootstrap

```bash
docker compose -f docker-compose.yaml -f docker-compose.garage.yml ps garage-init
# → should show "Exited (0)"

cat garage/credentials/s3.env
# → should contain non-empty S3_ACCESS_KEY=... and S3_SECRET_KEY=...
```
If `garage-init` failed (non-zero exit code): `docker compose logs garage-init` — the script stops at the first failure (`set -e`) with an explicit message.

### 6. Configure the bucket's CORS (required, same as option A)

```bash
cp scripts/s3-cors-config.example.json scripts/s3-cors-config.json
# Edit AllowedOrigins to your frontend domain/IP

aws s3api put-bucket-cors \
  --endpoint-url "$GARAGE_PUBLIC_ENDPOINT" \
  --bucket kagibi \
  --cors-configuration file://scripts/s3-cors-config.json
```
(AWS CLI configured with the `S3_ACCESS_KEY`/`S3_SECRET_KEY` read from `garage/credentials/s3.env` in step 5).

### 7. Verify end to end

```bash
curl http://localhost:8080/health
```
Then, in the app: create an account, upload a file, download it. If the upload hangs, see troubleshooting below — the typical symptom of a misconfigured `GARAGE_PUBLIC_ENDPOINT`.

### Maintenance

- **Update**: `git pull && docker compose -f docker-compose.yaml -f docker-compose.garage.yml up -d --build`. `garage-init` exits immediately on restart (`garage/credentials/s3.env` already filled), nothing is reapplied.
- **Backup**: back up `garage/data/` (objects), `garage/meta/` (Garage metadata), and `garage/garage.toml` (holds `rpc_secret`/`admin_token` — without them a restored node can't rejoin its own layout) — a regular ZFS snapshot of the dataset hosting these folders covers all three. `db_data/` (PostgreSQL) still needs a separate backup, same as option A.

### Troubleshooting

| Symptom | Likely cause |
|---|---|
| `docker compose up` refuses to start, `env file ... s3.env not found` | Step 2 not done |
| `GARAGE_PUBLIC_ENDPOINT manquant dans .env` at launch | Variable missing from `.env` (step 3) |
| `garage-init` errors on `layout apply` | A layout was already applied with a different version (e.g. `garage/credentials/s3.env` manually deleted after a first successful bootstrap) — check `docker compose exec garage garage layout show` and adjust manually if needed |
| Upload/download hangs from the browser, but `curl` on `/health` works | `GARAGE_PUBLIC_ENDPOINT` unreachable from the client machine (wrong IP, port not open on firewall/router), or CORS not configured (step 6) |
| `garage-init` stuck indefinitely on "waiting for the Garage node" | `garage.toml` missing or misconfigured (step 1) — check `docker compose logs garage` |
